# Stage 02: model calibration

Run `01_run_model_calibration.R` after stage 01. It builds the current preparation inventory, selects representatives, calibrates every representative sequentially on the GPU, publishes accepted CV budgets, regenerates `config.yml`, and verifies the generated configuration.

No representative identifiers need to be set manually. The calibration screens all eight candidates on three folds at sampling 100, then confirms the leading two on five folds and two repeats at production sampling 200. Only the most complex eligible unit in each analysis, tier, and resolution across continents and the most complex eligible time slice in each temporal profile are calibrated. Other spatial units and temporal profiles without eligible grouped CV of at least five folds inherit the conservative accepted budget from the same analysis, tier, and resolution. Production tuning retains eight initial candidates, three grouped repeats, and sampling 200, but uses the fold count selected by preparation: normally five, with higher grouped counts before leave-one-location-out when required by data feasibility.

Accepted results, rung checkpoints, and candidate-fold work checkpoints under `Data/Temp/Sjsdm_cv_calibration/` are reused after interruption when they match the current adaptive-calibration contract. Version-5 result/ladder signatures and version-3 work signatures exclude measured preparation runtime and the operational `basis_bytes` and `estimated_dense_matrix_bytes` fields. All observations, predictors, scaling, identifiers, fold assignments, seeds, spatial strategy, candidate grid and fitting settings remain hashed. Operational fields remain in the original preparation/provenance records. Exact older signatures are retained for verified migration; an old acceptance label or matching dimensions are not proof. Legacy version-4 evidence with changed memory measurements additionally requires independent reconstruction of its complete original input signature and exact analytical equality with current inputs. Original results are archived before migration, and earlier migration history is preserved. Never replace signatures to force reuse. Repeat 2 confirms the repeat-1 candidate when it is the exact winner or its normalized loss is within 2% of the repeat-2 minimum. Independent representatives continue after an individual failure, but publication blocks until every required result is accepted and content-matched.

Inventory, representative execution, and publication inspect the current preparation dependency graph before reading or reusing evidence. Always-cued configuration reads are compared with their cached values; disposable shared-memory handles are not recreated. Genuine upstream changes, missing data, or unknown always-cued work block calibration with the affected targets/store and the stage 01 recovery command. A preparation-only code difference can be cleared without rewriting stores only when rebuilding every fold in memory proves exact analytical equality. This protects completed CV/model descendants from a runtime-only cache rewrite; substantive MEM, response, scaling, or assignment changes still block reuse.

For a supplementary timing run, `run_sjsdm_cv_calibration_benchmark(maximum_budget_order = 2L, ...)` stops after the first two rungs, retaining the full ladder signature and unchanged convergence/stability gates. A bounded run with no accepted budget is incomplete evidence, not permission to publish a budget. It can resume later from its own checkpoint after approval. Production runners use the unbounded default; a bounded diagnostic must use an isolated evidence directory and must not publish production budgets automatically.

The scripts under `_components/` are implementation and recovery entry points. The master runner supplies their registered identifiers automatically.

After a fold-policy change, refresh affected prepared-fold targets before rebuilding the inventory. The new eligibility can select different maximum-complexity representatives. Accepted calibration results are reusable only when the candidate grid, prepared-fold content, structural fitting configuration, and calibration policy match their input hash. Changed representatives or prepared folds require calibration before publishing current production budgets; the ladder does not authorize resetting or bypassing calibration checks.

When a checkpoint belongs to different analytical inputs, archive that representative's calibration directory before restarting it, retaining the original evidence for audit. Do not remove prepared-fold targets or reset preprocessing. The calibration stage reports `incompatible_inputs`, `compatible_legacy`, `incomplete_preparation`, or `unreadable_inputs` in `budget_publication_blockers.csv`; `compatible_legacy` requires the master runner's verified migration, not a new GPU fit.
