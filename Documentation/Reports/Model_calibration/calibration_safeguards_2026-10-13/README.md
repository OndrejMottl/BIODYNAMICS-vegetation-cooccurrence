## Freshness safeguards

Calibration inventory, individual calibration, budget publication, and production tuning entry points now validate live preparation dependencies. Always-cued configuration is compared with cached values; genuinely changed files, commands, and upstream data block reuse with the affected store, target names, and stage 01 recovery command. Only the two known operational shared-memory handles are skipped, while their durable ancestors remain checked.

An error-handling-only preparation code change is not permission to reuse arbitrary cached data. When all upstream configuration and inputs are current, the guard can reconstruct the prepared folds in memory and require exact analytical equality. The known modern community-resolution mapper also has a narrow, read-only equality check; unknown commands or changed mapping results fail closed. Neither equality check runs targets or rewrites target metadata.

The live checks passed for paleo regional `eu_r005` functional types and modern continental Europe functional types. All target names, content hashes, and success timestamps in both inspected stores were unchanged before and after validation. The detailed measurements are in `preparation_validation.csv`.

## Bounded calibration

The diagnostic uses current prepared folds for paleo regional `eu_r005` functional types, the unchanged candidate grid and acceptance policy, and only the 500- and 1,000-iteration screening rungs. Screening uses 100 samples; any triggered confirmation uses the existing 200-sample policy. The bound allows at most 48 screening fits plus 20 confirmation fits. It must not progress to rung three, publish budgets, or restart modern production.

Evidence is isolated under `Data/Temp/Sjsdm_cv_calibration_bounded/20261013/project_paleo_spatial_regional/eu_r005/functional_type/`. The canonical script writes `bounded_benchmark_evidence.csv`, `bounded_fit_attempts.csv`, and `bounded_run_provenance.csv` here when it finishes. A `no_accepted_budget` result at the finite boundary is a valid diagnostic outcome, not evidence suitable for production publication. Timing estimates must distinguish this bounded window from the unknown cost of obtaining accepted evidence for all nine affected representatives.

The GPU timing run started in detached Rscript PID 22456 at 11:43:57 Prague (09:43:57 UTC), after the full test suite and both CZ smoke pipelines passed. Calibration itself ran from 11:44:51 to 12:02:17 Prague: **17 minutes 26 seconds**, or 18 minutes 20 seconds including launch/setup. It finished with an accepted diagnostic budget and all **68 of 68 fits converged**, zero fit/scoring errors, and complete five-fold coverage for both confirmation candidates in both repeats. The evidence validates against the current version-five input signature. See `bounded_validation.csv`, `bounded_timing_summary.csv`, `bounded_fit_attempts.csv`, and `bounded_accepted_budget.csv`.

The accepted budget is `n_iter_initial = 500`, `n_iter_max = 2000`, and `n_sampling = 200`. Screening selected `candidate_002`, which remained the winner at the next rung; candidate-loss rank correlation was 1.0 and normalized winner loss changed by 0.195%, below the existing 1% limit. Repeat two preferred `candidate_001`, with the selected candidate 1.07% worse. This passes the existing 2% practical-equivalence confirmation policy, **not** exact-winner equality. Both candidates converged on all five folds of each repeat. No convergence, screening, or confirmation threshold was changed for this diagnostic.

GPU fit time was 5.03 minutes for the 24 screening fits at 500 iterations/100 samples, 7.41 minutes for the 24 screening fits at 1,000/100, and 4.66 minutes for the 20 confirmation fits at 500/200. The maximum iteration budget was 1,000 in this run; the accepted 2,000-iteration production escalation ceiling was calculated, not fitted. The full diagnostic log remains at `Data/Temp/Calibration_safeguards_20261013/bounded_calibration.log`.

The accepted evidence remains isolated and **has not been promoted into the production representative directory or published into tuning CSVs/configuration**.
