apply_model_store_freshness_ledgerR Documentation

Apply the Model Store Freshness Ledger

Description

Marks store-freshness findings that a ledger row covers and adds a blocking finding for every ledger row that no longer covers anything.

Usage

apply_model_store_freshness_ledger(
  data_findings,
  data_ledger,
  vec_inspected_store_paths
)

Arguments

data_findings

Findings from [diagnose_model_store_freshness()] with an added 'store_path_relative' column.

data_ledger

Ledger from [load_model_store_freshness_ledger()].

vec_inspected_store_paths

Relative paths of every store inspected in this run. Ledger rows for other stores are ignored, so a scoped run never reports them as stale.

Details

A ledger row covers a blocking finding when the store paths are equal and its 'target_pattern' matches the whole target name. Non-blocking findings are never covered and stay 'informational'.

Value

'data_findings' with an added 'resolution_status' column ('blocking', 'ledger_covered', or 'informational'), followed by one 'stale_ledger_row' finding with status 'blocking' for each inspected ledger row that matches no blocking finding.

See Also

[validate_model_store_freshness()]

Examples

apply_model_store_freshness_ledger(
  data_findings = tibble::tibble(
    store_path = "/abs/Data/targets/a/pipeline",
    store_path_relative = "Data/targets/a/pipeline",
    target_name = "list_jsdm_variance_partition_genus",
    finding_type = "outdated",
    flag_blocking = TRUE,
    detail = NA_character_
  ),
  data_ledger = tibble::tibble(
    store_path = "Data/targets/a/pipeline",
    target_pattern = "list_jsdm_variance_partition_.*",
    reason = "lambda_cov = 0",
    evidence = "equivalence test",
    owner = "Ondrej Mottl",
    expiry_issue = "#999"
  ),
  vec_inspected_store_paths = "Data/targets/a/pipeline"
)
